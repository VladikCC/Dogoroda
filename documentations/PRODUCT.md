# Описание продукта: Агрегатор цен и поиска товаров по регионам (Беларусь)

## 1. Суть и миссия продукта
Продукт представляет собой **умный поисковик-агрегатор парсинга цен**, который собирает информацию о товарах из крупнейших интернет-магазинов (например, 5 Элемент, 21vek) и досок объявлений (Куфар). 

**Главная ценность для пользователя:** возможность вбить в поиск любой товар и на одном экране увидеть, где он стоит дешевле всего, учитывая его текущий город и стоимость доставки до него. 

Поскольку цены в сетевых магазинах могут отличаться в зависимости от региона, а стоимость доставки крупногабаритных товаров или посылок с Куфара сильно влияет на итоговую выгоду, сервис рассчитывает **полную стоимость владения (Товар + Доставка)**.

---

## 2. Ключевые функции (MVP)
* **Единый глобальный поиск:** Пользователь вводит название модели (например, конкретную вещ, телефон или бытовую технику).
* **Указание локации:** При регистрации или в шапке сайта пользователь выбирает свой город обитания (условно: Минск, Гродно, Витебск и т.д.).
* **Фильтрация и сравнение:** Система выдает список карточек товара из разных магазинов с сортировкой «от дешевых к дорогим».
* **Расчет логистики:** Возле цены каждого магазина пишется: *"Доставка в ваш город: [Цена / Бесплатно / Самовывоз]"*.
* **Прямой переход:** Сайт не продает товары сам. Каждая карточка — это умная ссылка с оригинальным ID, которая перенаправляет пользователя на страницу конкретного магазина для покупки.

## 3. Технологический стек и архитектура

Проект разделен на три независимых слоя по принципам микросервисной архитектуры для удобства масштабирования и DevOps-автоматизации:

### 1. Frontend (Клиентская часть)
* **Стек:** JavaScript (React / Vue.js или чистый JS по выбору разработчика).
* **Задача:** Быстрый, адаптивный под мобилки интерфейс, отправка поисковых запросов на бэкенд, вывод результатов в виде удобных карточек с фильтрами по магазинам и ценам.

### 2. Backend & Parsing (Серверная часть)
* **Стек:** Python (FastAPI), PostgreSQL (База данных), SQLAlchemy.
* **Компоненты бэкенда:**
    * **FastAPI:** Обрабатывает запросы от фронтенда (поиск, авторизация, фильтры).
    * **Парсер-воркеры (Scrapy / BeautifulSoup / Playwright):** Автономные фоновые скрипты, которые по расписанию (раз в сутки/несколько часов) обходят целевые сайты, собирают актуальные цены, ссылки, фото и складывают их в PostgreSQL. *Напрямую во время поиска пользователя парсинг не происходит во избежание блокировок и задержек.*
    * **Логический модуль доставки:** Скрипт, который сопоставляет город пользователя со стандартными тарифами доставки магазинов (или Европочты/Белпочты для Куфара) и рассчитывает итоговую цену.

### 3. DevOps & Инфраструктура
* **Контейнеризация:** Полная докеризация приложения. Каждый слой (`frontend`, `backend`, `database`, `parsers`) запускается в изолированном Docker-контейнере.
* **Оркестрация:** Управление всеми контейнерами на сервере через единый файл `docker-compose.yml`.
* **Веб-сервер:** Использование `Nginx` в качестве Reverse Proxy для распределения трафика, отдачи статики фронтенда и защиты бэкенда.
* **CI/CD:** Настройка пайплайна (GitHub Actions / GitLab CI) для автоматической сборки Docker-образов при каждом пуше в `main` и деплоя на удаленный Linux-сервер по SSH.
